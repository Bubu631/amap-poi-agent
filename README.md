# 命令行景点推荐 Agent（高德地图 MCP）

用自然语言输入「城市/出发地 + 游玩时长 + 兴趣偏好」，Agent 调用高德地图 MCP 搜索候选景点，推荐不超过 3 个景点，给出地址、开放时间、评分、推荐理由、游览顺序，以及景点之间的交通方式、距离和预计时间。所有数据以工具实际返回为准，取不到的字段标「暂无数据」。

## 快速查看

- [实际运行记录](RUN_RECORD.md)：杭州半日游、西安博物馆和冷门偏好场景，以及异常处理与校验测试记录。
- [核心实现](main.py)：MCP 工具调用、大模型规划、规则降级与证据校验。
- [大模型工具循环回归脚本](tests_fake_llm.py)：使用脚本化假模型，调用真实高德 MCP 验证结果；需要高德 Key。

这是命令行项目。GitHub 页面可直接查看源码和运行记录；执行新查询需按下面的步骤在本地配置高德 Key。仓库不包含 API 密钥。

## 启动

```bash
git clone https://github.com/Bubu631/amap-poi-agent.git
cd amap-poi-agent
python3 -m venv .venv && ./.venv/bin/pip install -r requirements.txt   # 需要 Python 3.10+
cp .env.example .env        # 填入 Key（.env 已在 .gitignore 中）
./.venv/bin/python main.py "周六在杭州游玩半天，喜欢历史文化景点，希望少走路，从杭州东站出发。"
```

不带参数运行会进入交互输入。常用选项：

| 选项 | 说明 |
|---|---|
| `--planner auto\|llm\|rules` | `auto`（默认）优先大模型，接口不可用时自动降级为规则规划器；`llm` 强制大模型；`rules` 强制规则 |
| `--max-steps N` | 大模型工具循环步数上限，默认 12 |
| `--save-log` | 把终端输出和完整工具调用轨迹保存到 `run_logs/` |
| `--json` | 以 JSON 输出结果 |
| `--quiet` | 不打印过程日志（过程日志走 stderr，结果走 stdout） |
| `--debug` | 出错时打印完整 traceback（已脱敏）；默认只打印一行错误说明 |

## 环境变量

密钥只从环境变量读取（支持同目录 `.env`），代码里不出现任何 Key。

| 变量 | 必填 | 说明 |
|---|---|---|
| `AMAP_MAPS_API_KEY` | 是 | 高德地图 Key |
| `AMAP_MCP_MODE` | 否 | `sse`（默认，直连 `https://mcp.amap.com/sse`）或 `stdio`（本地 `npx @amap/amap-maps-mcp-server`，需要 Node） |
| `LLM_API_KEY` | 否 | 大模型 Key（OpenAI 兼容接口）。不填或失效时自动降级为规则规划器 |
| `LLM_API_BASE_URL` | 否 | 例如 `https://api.zhizengzeng.com/v1` |
| `LLM_CHAT_PATH` | 否 | 默认 `/chat/completions` |
| `LLM_MODEL` | 否 | 例如 `gpt-5.6-luna` |
| `LLM_TIMEOUT` | 否 | 秒，默认 60；失败自动重试一次 |

## 使用示例

```bash
./.venv/bin/python main.py "周六在杭州游玩半天，喜欢历史文化景点，希望少走路，从杭州东站出发。" --save-log
./.venv/bin/python main.py "周日在西安玩一天，喜欢博物馆，带老人，从西安北站出发"
./.venv/bin/python main.py "在成都玩3小时，想看熊猫，从成都东站出发" --json
```

输出结构（终端）：需求解析 → 推荐景点（名称/地址/类型/评分/开放时间/建议停留/推荐理由）→ 游览顺序与交通（方式/距离/预计用时/公交线路）→ 总体说明 → 提示（无结果、工具失败、字段缺失、预算裁剪等）→ 工具调用记录。完整运行记录见 [RUN_RECORD.md](RUN_RECORD.md)。

## 工作原理

```
用户一句话
  │
  ├─ 1. 解析需求 ──► {city, origin, duration_hours, interests, constraints}
  │                   大模型解析；不可用则规则解析。缺项用默认值并在输出里说明
  │
  ├─ 2. 工具循环 ──► 启动时从高德 MCP list_tools 读出 15 个工具，转成 Function Calling 定义
  │                   模型每步决定调哪个工具，程序执行并把结果回填；上限 12 步
  │                   预期顺序：maps_geo 定位出发地 → maps_text_search / maps_around_search 搜候选
  │                   → maps_search_detail 拿坐标、评分、开放时间 → maps_direction_* 做每段路线
  │
  ├─ 3. 筛选排序 ──► 不超过 3 个；半天≈4h，每个景点 45~90 分钟
  │                   「少走路」= 优先彼此靠近的一簇，≤1.2km 才步行，远的公交/地铁，
  │                   公交方案步行段 >1.5km 则改打车；从出发地由近到远排序不走回头路
  │
  └─ 4. 程序校验 ──► 模型只输出 poi_id / 顺序 / 每段交通方式
                      名称、地址、评分、开放时间只从工具返回的证据库里取；找不到的景点直接剔除
                      距离、用时只从对应路线规划的返回里取；没有对应调用的一段标「暂无数据」
```

**为什么校验放在模型外面**：「地址对不对、距离是不是工具给的」这种事用规则判断最可靠。`Evidence` 类记录每次工具调用的原始返回，`verify()` 逐字段回查；模型编造的景点在最终输出里不可能出现。

**规则规划器（降级路径）**：大模型 Key 失效或接口超时时，程序自动切到确定性规划：相同的工具、相同的策略（城市级关键词搜 + 出发地周边搜 → 详情 → 高分且彼此靠近的组合 → 最近邻排序 → 逐段路径规划 → 时间预算裁剪），同样过校验层。输出里「规划器」一栏会标明用的是哪条路径。

## 异常处理

| 情况 | 处理 |
|---|---|
| 搜索无结果 | 大模型路径由提示词要求换关键词重搜；规则路径程序放宽为「景点」再搜一次；仍无结果则明确告知 |
| 工具调用失败 / 超时（30s） | 错误回填给模型让它换方式；记录到「提示」区并列出失败的步骤 |
| 高德 MCP 连不上 / Key 无效 | 一行人话报错并退出，错误信息中的密钥已脱敏，不打 traceback |
| 城市无法识别 | 校验层比对高德定位结果与需求里的城市，不一致时提示核对城市名 |
| 字段缺失 | 该字段显示「暂无数据」 |
| 大模型超时 / 失败 | 60s 超时，重试一次；仍失败则降级规则规划器 |
| 模型编造景点或字段 | 校验层剔除景点、覆盖字段 |
| 超出游玩时长 | 规则规划器先压缩每个景点停留时间（最少 45 分钟），仍装不下才舍弃末尾景点并说明；大模型路径通过提示词约束预算，尚无同等的程序级裁剪 |

## 文件

- `main.py`：全部逻辑（MCP 客户端、大模型客户端、需求解析、工具循环、规则规划器、校验、输出）
- `tests_fake_llm.py`：用脚本化假模型回归大模型工具循环和校验层（需要高德 Key），运行 `./.venv/bin/python tests_fake_llm.py`
- `requirements.txt`、`.env.example`
- `RUN_RECORD.md`：验收用例和自选场景的实际终端输出
- `run_logs/`：`--save-log` 生成的输出和工具调用轨迹（trace 已在 .gitignore 中）
